# Design Decisions

## DD-001 — SystemVerilog-2012

**Decision:** Use synthesizable SystemVerilog rather than a monolithic Verilog-2001 style.

**Reason:** Typed state enumerations, `logic`, `always_ff`, parameterization, and self-checking testbenches improve readability and verification while remaining compatible with current Quartus/Questa workflows.

## DD-002 — 50 MHz single-clock architecture

**Decision:** Keep the complete platform in the DE10-Lite 50 MHz clock domain and use clock-enables for sample/VGA rates.

**Reason:** It simplifies CDC reasoning and timing closure. SPI SCLK is an external output generated by stateful logic rather than an internal fabric clock used by other RTL.

## DD-003 — ADXL345 mode 3, 1 MHz SCLK

**Decision:** Use 4-wire SPI mode 3, MSB first, nominal 1 MHz SCLK.

**Reason:** Analog Devices specifies mode 3 in its ADXL345 quick-start guidance. A conservative 1 MHz rate leaves comfortable margin while easily completing seven-byte XYZ transactions within a 10 ms sample interval.

## DD-004 — 100 Hz / full-resolution ±4 g baseline

**Decision:** Configure `BW_RATE=0x0A`, `DATA_FORMAT=0x09`, and `POWER_CTL=0x08` after a successful `DEVID=0xE5` read.

**Reason:** 100 Hz is sufficient for visible motion/shock experiments and creates a simple 10 ms sample cadence. Full-resolution mode preserves the approximately 3.9 mg/LSB scale. ±4 g offers more headroom than ±2 g without forcing a larger numeric representation.

## DD-005 — Byte-oriented SPI/controller boundary

**Decision:** Separate `spi_byte_master` from `adxl345_controller`.

**Reason:** The electrical transfer engine can be tested independently from sensor register sequencing. The controller can be verified with a deterministic byte-level mock without coupling every protocol test to bit timing.

## DD-006 — Saturating calibration

**Decision:** Offset subtraction saturates instead of wrapping.

**Reason:** Wraparound turns an out-of-range correction into a physically misleading sign reversal. Saturation produces a deterministic failure boundary.

## DD-007 — Fractional-accumulator IIR

**Decision:** Use `alpha=1/8` and eight internal fractional bits.

**Reason:** A power-of-two coefficient maps to an arithmetic shift and avoids multiplier cost. Fractional state prevents the filter from stalling on small integer differences.

## DD-008 — Squared magnitude, no square root

**Decision:** Compare `X²+Y²+Z²` against a squared threshold.

**Reason:** The event decision does not need the magnitude itself. Eliminating square root reduces latency/resources and produces straightforward reference-model tests.

## DD-009 — Sample-domain event timing

**Decision:** Dwell, hold, and recovery counters advance only when `sample_valid` is asserted.

**Reason:** Event behavior then depends on sensor samples, not the 50 MHz implementation clock, making the state machine deterministic across internal pipeline changes.

## DD-010 — 256-record inferred memory

**Decision:** Use a parameterized SystemVerilog memory array for the triggered logger rather than instantiating vendor RAM IP in source.

**Reason:** This keeps simulation portable and allows Quartus to infer block memory. A later Quartus report will determine the actual M9K implementation and resource cost.

## DD-011 — Vendor pin assignments are imported, not guessed

**Decision:** Do not hard-code or redistribute a copied Terasic Golden Top QSF. Provide a script that imports only the assignments required by this project from the user's official DE10-Lite System CD.

**Reason:** This avoids transcription errors, keeps the repository independent of vendor redistribution terms, and makes the hardware mapping traceable to the official board package.

## DD-012 — VGA remains a should-have

**Decision:** Implement and simulate the 640×480 timing/status baseline now, but keep it isolated from the core acquisition/control requirements.

**Reason:** VGA adds useful visual demonstration value without being allowed to block the must-have sensor/DSP/control/logger path.
